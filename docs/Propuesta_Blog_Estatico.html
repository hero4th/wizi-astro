PROPUESTA: Volver a sitio 100% estático manteniendo el panel de administración

1. Antecedentes

Tras la migración del sitio de Vercel a Netlify, el blog quedó funcionando de forma completamente dinámica, consultando la base de datos de Netlify en cada visita que recibe un usuario.

Esto está generando un consumo innecesario de dicha base de datos, cuando realmente solo necesitamos acceder a ella al momento de gestionar el contenido, no para mostrarlo al público general.

2. Objetivo

Reducir drásticamente el consumo de la base de datos de Netlify, manteniendo la misma agilidad para agregar, editar y publicar entradas desde el panel de administración /admin, pero regresando el sitio web a un modelo 100% estático para todos los visitantes.

3. Propuesta: "Estático con gestor aislado"

La solución consiste en separar la gestión del contenido de su visualización pública. El panel de administración será el único lugar que acceda a la base de datos. El sitio público nunca la consultará.

¿Cómo funcionaría?

  1. Gestión aislada – El administrador seguirá creando, editando, publicando o eliminando entradas desde /admin. Únicamente estas acciones utilizarán la base de datos de Netlify.
  2. Generación de snapshot – Al guardar o publicar una entrada, el sistema exportará automáticamente TODAS las entradas publicadas a un archivo blog.json.
  3. Reconstrucción automática – Ese guardado disparará un Build Hook de Netlify, el cual iniciará un nuevo build del sitio.
  4. Generación estática – Durante ese build, Astro leerá el archivo blog.json y generará todas las páginas del blog (/blog/, /blog/[slug]) de forma estática.
  5. Sitio 100% estático para el público – Los visitantes verán las páginas pre-generadas, sin realizar ninguna consulta a la base de datos.

4. Ventajas de esta propuesta

VentajaExplicación
Menor consumoSolo se consulta la base de datos de Netlify cuando se entra al panel /admin para gestionar contenido.
Mayor rendimientoLas páginas del blog se cargarán mucho más rápido al ser 100% estáticas.
Menor costoSe reduce el uso de consultas y consumo asociado a la base de datos.
Mayor seguridadLa base de datos queda completamente aislada del público. Solo es accesible desde las rutas protegidas del panel.
Sin perder agilidadSeguiremos pudiendo publicar, actualizar o eliminar blogs desde el mismo panel con el que ya trabajamos hoy.
EscalableEl sitio podrá recibir mucho más tráfico sin aumentar el consumo de la base de datos.
Fácil de mantenerEs una solución limpia, probada y fácil de entender para este proyecto.

6. Recomendación

Recomiendo aprobar esta implementación.

Esta propuesta nos permite volver al modelo 100% estático, resolver el problema de consumo de la base de datos de Netlify y conservar la comodidad del panel administrativo actual. Con esto logramos eficiencia, ahorro y una mejor experiencia tanto para quien administra el contenido, como para nuestros visitantes.
